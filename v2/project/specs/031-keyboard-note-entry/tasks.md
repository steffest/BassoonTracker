## Found while doing it

- **design.md's own `resolveNote` sketch had a real bug, caught before writing the implementation's test.** The sketch computed `noteOctave`/`noteIndex` from the raw semitone `offset` alone; v1's own math (`input.js:744-745`) computes them from the *combined* `octave*12+offset` index instead - the first test written against a hand-traced example (C at keyboard-octave 1 → period 856) did not match the sketch's formula, which is what surfaced it before any code shipped. The fix also had to preserve v1's own override (`input.js:538`): the OFF key's combined index is forced to literal `0` regardless of octave, or it would never resolve to `OCTAVENOTES`' `"OFF"` entry at all. `domain/song/keyboardNotes.js` as implemented includes both corrections, with the override documented inline.
- **`song.putNote`'s options-object signature is not a drop-in replacement for v1's positional `Editor.putNote(instrument, period, ...)` when clearing a note.** `putNote({instrument:0, period:0})` clears correctly because `period: 0` satisfies `typeof period === "number"`; the design sketch's first draft wrote `putNote(0, 0)` (positional, silently ignored by the destructured signature), which would have left the existing period untouched instead of clearing it - caught by reasoning through spec 028's own `putNote` before writing `clearCurrentColumn`, not by a failing test.
- **A Ctrl/Cmd-held letter needed an explicit guard the requirements/design pass had not flagged as a distinct risk until re-reading `input.js:499-521`.** Without it, `Ctrl+Z` (a plausible future undo shortcut) at the note column would have written a "Z" note instead of doing nothing, since the character-key fallthrough had no reason on its own to treat a modified keypress differently. v1 checks this before its own keyboard-table lookup for the same reason; `handleCharacterKey` now does too, and the test suite includes the exact `Ctrl+KeyZ` case as a named regression check.
- **Spec 030's own `ArrowUp`/`ArrowDown`/`PageUp`/`PageDown` were wrong**, not merely incomplete - ported from `patternView.js`'s mouse-wheel guard rather than `input.js`'s own keyboard cases, which wrap (arrows) and jump by a quarter-pattern (Page keys) rather than clamping/stepping by a fixed 16. Corrected here since this spec was already re-reading and rewriting the exact same keydown surface; recorded as NOTE-010 rather than silently overwritten.
- **Everything else matched the plan going in**: `domain/song`'s existing mutation/selection/undo primitives needed no changes at all beyond the new state and resolvers; `capabilities.js`'s `record.toggle` mapping worked on the first `build.mjs` run, producing exactly the wrapper shape `transportToggle.js` already established; the FastTracker-specific test (against a real `sin.xm` load) passed on the first run once the volume-mnemonic assertion was rewritten to compare against a direct `putNoteParam` call instead of hand-deriving the bit-packed value (see the test file itself for why: the packing has a `+1` offset baked into spec 028's own `putNoteParam`, not this spec's concern to re-verify).
