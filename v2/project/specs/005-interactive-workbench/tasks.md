# 005 — Implementation phases

Status: all five phases implemented and verified (compiler, generic canvas preview, source inspection, Node save/convert service with in-browser editing, Interact-mode tracing with State gallery and Interaction log, end-to-end acceptance and reference documentation). Known limits are listed under Phase 5 and in `project/documentation/interactive-workbench.md`.

## Phase 1 — Source graph to simplified preview

Goal: render the supplied YAML hierarchy with inspectable limitations.

- [x] Select a small source-range-preserving YAML parser and document provenance. (`compiler/yaml.js`; project-owned, MIT, scoped to the authored subset — see `project/documentation/compiler.md`.)
- [x] Implement name resolution/generated identities, comma-label variants and independent layout fields. (`compiler/identity.js`, `compiler/labels.js`, `compiler/layoutFields.js`.)
- [x] Implement supported prose recipes, generated bindings and source-located warning lists. (`compiler/recipes.js`, `compiler/convert.js`.)
- [x] Extend normalized tree/runtime support and use placeholders for unsupported nodes. (`runtime/genericLayout.js`, `renderers/canvas/mountGeneric.js`; unsupported nodes draw as a dashed placeholder box with type/name and source provenance.)
- [x] Test references/collisions, deterministic supported conversion, malformed source and preserved output. (`v2/tests/{yaml,compiler,genericLayout}.test.js`.)

User verification: `node v2/compiler/generate.js` converts app.yaml into `project/specs/application/app-outline.json`; opening `v2/preview-app.html` over plain HTTP shows its panels/controls (top toolbar, controlBar buttons/radio group, status bar, song-properties panel) and an 11-item warning list (two unresolved menu actions, one unresolved component reference, three unsupported-component placeholders, four unresolved rule interpretations, one ambiguous-duplicate-name) in both the on-page diagnostics panel and the browser console. Manually confirmed with chrome-devtools at two viewport widths; no console errors from the app itself. A syntax error in a referenced file (verified with a synthetic fixture in `compiler.test.js`, not by breaking real source) is a hard failure that leaves the previous `app-outline.json` untouched rather than overwriting it with a partial result. Known cosmetic gap: two notification-light placeholders inside the fixed-height top toolbar visually overlap each other (documented in `compiler.md`; does not cascade into other panels).

## Phase 2 — Point to source

Goal: select rendered components and find their authored definitions.

- [x] Build split-pane workbench, file tree, text buffers and preview message bridge. (`v2/workbench.html`; file tree/text buffers are read-only, fetched directly — the Node service with a real save/convert API is Phase 3.)
- [x] Expose layout bounds/ancestry/clipping; add hover and selection overlays. (`renderers/canvas/mountGeneric.js` tracks paint-order rects each layout pass and draws hover/selection outlines; clipping specifically is not yet exercised since no current component scrolls/clips its content.)
- [x] Add Inspect/Interact modes, breadcrumbs and definition/use-site navigation. (Toolbar + on-canvas breadcrumbs in the iframe, mirrored in the workbench's details panel; Interact mode is a mock `console.info` dispatch stub, since no live store/dispatcher exists until a later phase.)
- [x] Test hit-testing at multiple scales, nested references and stale source ranges. (`runtime/hitTest.js` + `v2/tests/hitTest.test.js`: paint-order hit-testing through 3+ levels of nesting, ancestry chains, and pointer-mapping at a non-1:1 CSS/logical scale. "Stale source ranges" is covered by the workbench's per-file hash check against `app-outline.json`'s `sourceFileHashes`, manually verified by reasoning about the code path rather than by editing a real file on disk during the session — there is no automated test for it yet.)

User verification: hover the control bar (status line updates via `v2:hover`), select Play (opens `components/controlBar.yaml` with the button block selected, shows ancestry/definition/contributing-rule links), then select its parent via the `main` breadcrumb (opens `app.yaml`, selection widens to the whole root panel). Confirmed with chrome-devtools that clicking in Inspect mode never logs a dispatch, and the identical click in Interact mode logs `[interact] would dispatch "transport.toggle"`.

Found and fixed one real bug in this phase: `convert.js`'s binding literals were built as `{ kind: "rule", ...result.binding }`, and the spread's own `kind` (from the recipe, e.g. `"visual-state"`) silently overwrote the outer `"rule"`/`"action"` label — which broke both the workbench's "contributing rules" panel and Interact mode's dispatch lookup. Fixed by using a separate `origin` key that the spread can't touch, with a regression test in `compiler.test.js`.

## Phase 3 — Save files and refresh

Goal: develop directly against local YAML from the browser.

- [x] Implement built-in Node static server and constrained read/save/convert APIs. (`v2/server.mjs`, run as `node v2/server.mjs`, default `http://127.0.0.1:8877/workbench.html`, `PORT` env overrides. Loopback only, Host-header check, per-process write token, `.yaml`-only paths containment-checked (including realpath) against `project/specs/application/current`, replace-existing-only writes via temp file + rename; `GET /api/{token,files,source,outline}`, `PUT /api/source`, `POST /api/convert`. Exported as `createWorkbenchServer()` so tests run the real handler on an ephemeral port.)
- [x] Add Save & Refresh, Ctrl/Cmd+S, dirty buffers and separate save/generation statuses. (`v2/workbench.html` detects the service via `/api/token`; on a plain static host it stays read-only exactly as in Phase 2. Per-file buffers keep text/disk hash/selection/EOL across file switches, dirty markers in tree and header, `beforeunload` guard, `save` and `generation` status lines kept separate, warning list printed to the browser console per conversion.)
- [x] Add conflict detection, validated replacement and generation ordering. (Server: 409 with current disk text/hash on base-hash mismatch, 422 with located errors for invalid YAML, one in-process mutation queue, and `runConvert` re-hashes every input after compiling and retries when an external editor changed a file mid-conversion. Workbench: conflict bar with explicit "discard mine"/"overwrite disk" choices, invalid YAML stays a local draft with the error range selected, hard compile failure reports "saved; preview stale (previous generation kept)".)
- [x] Test path containment, conflicts, write failures and external changes during conversion. (`v2/tests/server.test.js`, 16 cases: containment incl. `..`/absolute/drive-letter/non-yaml/symlink escape, foreign Host header, missing token, atomic replace, never-create, 409 + rebase, 422 + untouched disk, read-only-dir write failure, publish + per-file hashes, save-then-convert, hard failure retains outline, save/convert race on separate connections, no-store static serving. Two cases are skipped on Windows where symlink creation needs elevation and read-only directories don't block writes.)

User verification: change Play's label and a panel layout, save, reread disk and see the updated preview. Editing externally produces a conflict; valid source with conversion errors reports saved-but-stale. **Done** with a headless-Chrome CDP script against the real `node v2/server.mjs` (42 checks): selected Play through the bridge, edited `label: Play` to `Start`, switched to `app.yaml` and back (edit retained), Ctrl+S saved, disk reread showed `Start` with CRLF preserved, `/api/outline` and the reloaded canvas showed START; the selection was reported as gone because the label is part of the generated identity, and a later layout-only save of `songProperties.yaml` proved a selection with unchanged identity survives regeneration without the editor jumping files. External edit → 409 conflict bar, not overwritten; discard reloads disk text and flags "stale: disk changed since the last generation". `bad: [oops` → 422 "not saved: invalid YAML", disk untouched, draft still dirty. Replacing `app.yaml` with valid YAML lacking `app.ui.main` → saved on disk, "saved; preview stale (previous generation kept): ERROR [missing-app-ui-main] …", previous `app-outline.json` byte-identical, canvas still alive. All three files were restored through the UI and confirmed byte-identical to their originals afterwards; no console errors other than the intentionally printed diagnostic. Also verified read-only fallback under `python -m http.server` (buffer read-only, Save disabled, Ctrl+S inert, six files listed from `app-outline.json`).

Found and fixed three real bugs during this pass, none of which the unit tests could see: (1) a `<textarea>` reports LF regardless of the file's line endings, so the first save rewrote every line of a CRLF file — buffers now remember the file's EOL and restore it on save (a file that already mixes CRLF/LF, like the original `controlBar.yaml` with 19 of 24 lines CRLF, is unified to CRLF on its first save; documented, not hidden); (2) the Save & Refresh button had no click handler — only Ctrl+S worked; (3) the file header updated before the file's content had loaded, so a fast click on Save right after switching files hit a disabled button.

## Phase 4 — Component development tools

Goal: use State gallery and Interaction log during refinement.

- [x] Add labeled supported button-state fixtures and isolated mock commands. (`v2/workbench/stateGallery.js` + `renderers/canvas/buttonSkin.js`: for any supported button/radio item in the outline, forced fixtures for default/hover/pressed/focused/disabled plus on/off when the node carries a `visual-state` binding, drawn by the same `drawButton()` the live renderer uses and labeled "Illustrative … no controller, no commands". A live example runs the real `runtime/buttonController.js` against a private mock state and traces as renderer `gallery`; it has no path to the preview or its commands.)
- [x] Add real interaction tracing, filters, pause/resume, clear and bounded history. (`renderers/canvas/mountGeneric.js` Interact mode now feeds pointer/keyboard input through a per-control `buttonController`, dispatches the node's generated `command` bindings against an explicit mock state (`mockField`/`mockValues`, shown in the preview toolbar), and emits `v2:trace` events for every input, state transition, activation result and command, stamped with one sequence counter and time origin at the emitting boundary. `runtime/traceCollector.js` is the bounded ring buffer (capacity 500, explicit dropped count, paused-events count separate from drops, display-only filters); `v2/workbench/interactionLog.js` is its UI with Pause/Resume, Clear, instance and kind filters and an always-visible status line.)
- [x] Link gallery/live selections to source and generated behavior diagnostics. (Log rows select their instance in the preview, which opens its source; the gallery has Open source / Select in preview, lists each generated binding as a link to the prose that produced it, and lists the compiler diagnostics attached to that node. The details panel gains a "mock: disabled" toggle (`v2:setDisabled`) and a "show in State gallery" link. Fixed a real compiler gap this exposed: the `highlighted-when-active` rule recipe derived mock fields (`song.playback`, `recording`) that never matched the action recipes' fields (`playback.status`, `record.active`), so no highlight could ever follow a command; `compiler/recipes.js` now maps condition subjects through a small alias vocabulary with an explicit `activeValue`, with a regression test.)
- [x] Test disabled/keyboard/pointer behavior and inspection/interaction separation. (`tests/buttonController.test.js` (6) and `tests/traceCollector.test.js` (5): press/release, release-outside, Enter-on-keydown / Space-on-keyup, unfocused and disabled attempts reported as blocked with no activation, ring-buffer drops, pause counters, view-only filters, clear. Separation and the rest of the browser behavior are covered by the headless-Chrome run below.)

User verification: inspect button states, switch to Interact, activate a button and read input → state → command. Gallery fixtures never invoke application commands. **Done** with a headless-Chrome CDP script against `node v2/server.mjs` (36 checks): a real click on Play in Inspect mode selected it and traced nothing; the same click in Interact mode traced `input pointerenter → state hover → input pointerdown → state focused, pressed → input pointerup → state pressed false → activation dispatched → command transport.toggle playback.status stopped → playing → state highlighted true`, the canvas drew Play highlighted and the toolbar readout showed `playback.status=playing`; Enter (keydown) and Space (keyup) each dispatched again; with "mock: disabled" checked the click traced `activation blocked-disabled` and no command; the selection survived switching modes; Pause counted 10 uncaptured events without adding rows, the `input` kind filter hid 10 rows and said so, Clear reset to 0/0; the gallery listed the four interactive nodes, drew the seven Play fixtures with captions, linked bindings and diagnostics, and clicking its live example traced under renderer `gallery` while the preview's mock state stayed `stopped`; the gallery's disabled toggle produced a blocked activation and no command; and the standalone `preview-app.html` made 13 requests, none for `workbench/` modules or `traceCollector.js`. Screenshots reviewed. Not covered: radio-group items are traced and visually select as mock UI state but have no command (their prose rules are still unresolved warnings); `shortKey` values in YAML are not bound.

## Current outcome

Implemented and verified 2026-09-10 in five phases (see each phase above for evidence). `node v2/server.mjs` serves `http://127.0.0.1:8877/workbench.html` (authoring), `/app.html` (the user-facing application with no authoring chrome, added 2026-09-10 after the phases closed) and `/preview-app.html` (the app with Inspect/Interact tools, embedded by the workbench); `node v2/compiler/generate.js` regenerates `app-outline.json` without the service; `app.html` and `preview-app.html` run from that artifact on any static host. Labels and natural-language rules remain as authored; the compiler adds generated bindings and source-located warnings beside them. The original specification note stands: the authorized YAML cleanup separated type/layout, fixed noDependencies and nested radio-group items; no further source rewriting was performed by the implementation.
