# 007 — Implementation

Status: implemented and verified 2026-09-10.

- [x] Node constructors and app state for generated code. (`runtime/components.js`: `panel`/`radioGroup`/`radioItem`/`button`/`label` producing renderer-shaped nodes with `highlightedWhen`/`onActivate` hooks, `ensureIds` mirroring the compiler's identity rule; `runtime/appState.js`: the spec-003 store plus `onAnyChange`.)
- [x] Renderer hooks for code-defined behavior. (`renderers/canvas/mountGeneric.js` accepts `state`, `appContext` and `assetBase`, honors `node.onActivate` (sync or async) and `node.highlightedWhen` before outline bindings, redraws on any state change; `renderers/canvas/{skin,assets}.js` take a configurable asset base with per-base caching.)
- [x] Emitter. (`compiler/emit.js`: one `ui/<container>.js` per authored panel, one lazy `actions/<command>.js` per command (delegating import when `capabilities.js` maps it, documented mock otherwise), `state.js` seeded command-first, `main.js`, `config.js`, `index.html`, `README.md`, `LOOSE-ENDS.md`; unsupported nodes omitted with an inline comment, containers that lose every child flagged, every warning covered once.)
- [x] Build CLI. (`build.mjs app|dist|all`; `app` needs only Node and refuses to clear a folder without the `.generated` marker; `dist` uses esbuild with code splitting, hashed names, minification, no comments, a plugin swapping `config.js` for the copied asset location, copies the skin, rewrites `index.html`, writes `build-manifest.json`. `package.json` gains scripts and esbuild as the single devDependency; `.gitignore` covers `node_modules/` and `dist/`; `app/` is committed.)
- [x] Capability manifest hook. (`capabilities.js`, empty by design: nothing real exists to map yet; the emit test proves the delegation path.)
- [x] Verify.

Verification: `node --test "v2/tests/*.test.js"` 95 passing (85 prior + 7 `emit.test.js` cases executing the generated modules in Node: module set, tree parity with the outline's supported nodes, hook types and predicate results, command-first state seeding, mock action toggling via the lazy hook, capability delegation, loose-end coverage and no dangling commas; + 3 `components.test.js` cases). Build outputs for the current YAML: `app/` 15 files, 6 UI modules, 2 mock actions, 2 state fields, 16 loose ends; `dist/` entry 22.8 KB minified plus two feature chunks of 217 and 191 bytes, skin assets copied, no comments in output. Headless-Chrome run (18/18) against `app/index.html` on the workbench server and `dist/index.html` on a static host rooted at `dist/`: no chrome, no `app-outline.json`/API/workbench/vendor/compiler requests, `dist` startup requests exactly the manifest entry and the two skin assets, the feature chunk is fetched only on the first Play activation (`[app] transport.toggle` logged, `recordToggle` never requested), no console errors, no failed requests. Screenshots of both reviewed: identical to the source-run app minus the placeholder boxes; the emptied `notifications` panel remains as a small empty box and is listed as a loose end.

Known limits: the generated app imports the shared library from `../runtime` and `../renderers`, so `app/` is not deployable on its own (deploy `dist/`, or the whole v2 folder); no source maps in `dist/` (add `sourcemap: true` in `build.mjs` if wanted); the asset PNG is copied unhashed; no PWA manifest/service worker; Windows cloud-sync folders can briefly lock freshly written files, so the build retries folder removal.
