# v2 project process

All edits for this project stay inside `v2`. Parent application code may be inspected as a reference.

Read `project/specs/index.md`, `project/specs/product.md` and the relevant numbered spec before starting feature or research work. Follow `project/documentation/specification-workflow.md`.

Each significant feature or research change gets a new sequential `project/specs/NNN-slug/` folder with `requirements.md`, `design.md` and `tasks.md`. Phases need observable verification; outcomes may be documentation, experiments, models, assets or code. Record evidence and keep specification completion distinct from implementation completion.

The YAML graph rooted at `project/specs/application/current/app.yaml` is the single application source, including its appearance: `skin/<name>.yaml` (spec 008) says which source PNG under `v2/assets/skin/src/` draws which visual state of which component type, and a component links to a style variant with `variant:`. Development loads those PNGs individually; `node v2/build.mjs skin` packs the referenced ones into `v2/assets/skin/generated/atlas.{png,json}` for the generated app and the bundle. Never hardcode a sprite name, 9-slice inset or font metric in the renderer again; author it. Real capabilities live behind one boundary each under `v2/domain/` and are wired in through `v2/capabilities.js`; only the generated application reaches them, and only their own index module may be imported from outside (spec 012 is the first, playback). Component types are declared once in `v2/runtime/componentTypes.js` (spec 009): add a type there, add a draw kind only if it looks like nothing that exists, and never branch on a type name anywhere else - a test enforces this. A type also declares its interaction `behavior` and its `cursor` there (spec 014); the behavior name resolves through `v2/runtime/behaviors.js`, which is the only map from a behavior to a controller, and gesture recognition (capture, drag, double-click) is pure and lives in `v2/runtime/pointerRouter.js`, never in the renderer. A `capabilities.js` key beginning `host.` is a hook the renderer offers the application rather than a command compiled from the YAML. `v2/assets/skin/generated/` is build output. `project/specs/application/app-outline.json` is its generated runtime artifact (spec 005 compiler: `node v2/compiler/generate.js`, or Save & Refresh in `node v2/server.mjs`); `outline.json` is spec 003's earlier fixed-template example. final-spec.md is historical context. Use Git history, not copied revision folders or manual application-spec versions. Keep numbered change specs and progress; newer specs explicitly supersede old policies.

Update relevant domain documentation and `project/documentation/index.md` when adding documentation. Use meaningful automated tests for behavioral code changes and appropriate manual/artifact checks for documentation and visual changes.

The project runs from static source without a required build. Third-party code is allowed only as a vendored, provenance-documented bundle under `v2/vendor/` used by the authoring workbench (see `v2/vendor/codemirror/README.md`), plus esbuild as the single devDependency for the optional release bundle (`node v2/build.mjs dist`, spec 007); runtime, renderer and compiler modules stay dependency-free and the generated application ships none of it. `v2/app/` is generated output (committed, never hand-edited; rebuild with `node v2/build.mjs app`); `v2/dist/` and `v2/node_modules/` are ignored. Specification authoring/generation is a development activity, never a prerequisite at application startup. Canvas remains a first-class renderer and uses the existing bitmap-font conventions.

Spec 005 governs authoring: use names or generated IDs, not mandatory authored IDs; retain comma-separated label variants and prose rules/actions. Generate bindings in outline.json and print source-located warnings for unresolved behavior. Outline/code generation during development is allowed. Syntax/structural errors retain the last working output. Reverse code-to-YAML synchronization is deferred.
